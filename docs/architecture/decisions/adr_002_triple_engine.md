# ADR-002: 三重"与"判定逻辑

- **状态**: 已采纳
- **日期**: 2026-05-13
- **决策者**: BanSafe Team

---

## 背景

安全监控系统需要在**漏报率**（false negative）和**误报率**（false positive）之间做权衡：
- 单一传感器（如仅加速度计）容易因日常活动（跳跃、搬重物）导致误报
- 多传感器级联判定可显著降低误报率，但实现复杂度更高
- 原 dayplan 中提及三重判定，但代码中旧 `main.c` 的阶段2/阶段3 任务为空壳

## 决策

采用三重级联"与"逻辑：
1. **阶段1 - 姿态异常**：加速度计偏差评分 ≥ 40 → 触发阶段2
2. **阶段2 - 音频异常**：音频特征评分 ≥ 60 → 触发阶段3
3. **阶段3 - 视觉异常**：视觉 AI 评分 ≥ 80 → 触发最终报警

只有**全部通过**才触发报警。

### 设计说明与当前局限

| 项目 | 状态 |
|------|------|
| 阶段1 - 姿态检测 | ✅ 已实现（基于 QMA7981） |
| 阶段2 - 音频分析 | ❌ 占位代码，始终返回 -1。当模块未就绪时，引擎自动跳过（视为放行），但仍记录日志 |
| 阶段3 - 视觉分析 | ❌ 占位代码，同上 |

### 跳过策略

当某阶段模块不可用时（如音频驱动未完成）：
- `safety_engine_run()` 将该阶段评分置 0，记录 WARNING 日志
- **不阻断级联**：相当于该阶段"放行"
- 这意味着在只有阶段1就绪时，算法退化为单姿态判定（误报率较高，需后续补全模块）

## 后果

### 正面
- 多模态融合可大幅降低误报率
- 级联结构节省算力（早期阶段过滤掉大多数正常状态）
- 模块独立，可逐步实现

### 负面
- 当阶段2/3未就绪时退化为单模态判定
- 三级阈值调参需要大量实测数据支撑
- 音频和视觉模块的延迟会影响端到端响应时间

## 替代方案

| 方案 | 理由 |
|------|------|
| 单传感器判定 | 误报率高 |
| "或"逻辑（任一触发即报警） | 误报率更高 |
| 加权投票（软融合） | 实现复杂，当前阶段不需要 |
| 贝叶斯融合 | 需要统计先验数据，当前不具备条件 |

2. 完成 OV2640 摄像头驱动 → 集成 TFLite Micro → 实现 `safety_engine_evaluate_visual()`

4. 添加场景自适应阈值（如夜间模式降低视觉阈值）
